# Security Notes

Llama Nexus is designed for **single-user, local use**. This page explains
the default posture and how to harden it when needed.

## Defaults (safe for local use)

- The web UI (3002) and management API (8700) bind to **127.0.0.1** —
  reachable only from your own machine.
- No management authentication by default (local trust model).
- The inference API key (`API_KEY` in `.env`) is generated by the installer.
- All inference, storage, and processing run locally — no telemetry, no
  cloud calls (except model downloads from HuggingFace).

## Exposing Llama Nexus on your LAN

If you want other devices on your network to use it:

1. Open **Settings → Network exposure** and flip **Expose UI & API on the
   LAN** — the backend rewrites `BIND_HOST` in `.env` for you and remembers
   the choice. (Or set `BIND_HOST=0.0.0.0` in `.env` by hand.)
2. **Set `MANAGEMENT_AUTH_TOKEN`** (the Settings page suggests a random
   token you can copy; or `openssl rand -hex 24`). This is strongly
   recommended: without it, anyone on the LAN can control services,
   download/delete models, and read logs. With it, all `/api/v1` routes
   require `Authorization: Bearer <token>`.
3. Restart: `docker compose -f docker-compose.yml -f docker-compose.prebuilt.yml up -d`.

Do **not** port-forward the UI/API through a router without an additional
reverse-proxy auth layer in front.

## Trust boundaries to be aware of

- The management backend mounts the Docker socket (it orchestrates sibling
  containers). Anyone with management API access effectively has host-level
  control. Keep it local or token-gated.
- Model files come from HuggingFace repos — review repos before downloading,
  as with any model hub.
- Qdrant ships without an API key locally (`localhost:6333`); set
  `QDRANT_API_KEY` in `.env` if you expose ports.
- Neo4j (GraphRAG profile) uses the `.env` credentials; change the default
  password before enabling the graphrag profile on a shared machine.

## Where your data lives

| Data | Docker volume |
|---|---|
| Downloaded models | `gpt_oss_models` |
| Conversations | `conversation_data` |
| RAG documents/index | `backend_data`, `qdrant_data` |
| Backend configs | `backend_data` |

`docker compose down -v` deletes all of the above — treat it as a wipe.

## Reporting issues

Open a GitHub issue for suspected security problems; please avoid posting
exploit details publicly until reviewed.
